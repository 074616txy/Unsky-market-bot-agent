## 前言

- 前面已经实现了关于商品模块的相关功能，包括简单的商品查询、商品分析和关键词搜索等功能，这些功能都是与skybot的`product_tool`有关，在这个商品工具模块进行具体的功能实现；接下来，我们就要在这些具体的商品操作里加入用户上下文。

**最小闭环**

```
1. Java后端调用 /api/user/info 获取用户信息
2. Java对敏感的字段进行整理和过滤，比如"token"
3. Java 调 Skybot 时把 user_context 传给 Python
4. Python Agent 把 user_context 放进 Prompt
5. 将Prompt传给LLM进行分析，在将最终结果返回给用户
```

- 具体区分

```
user_id 是“谁在问”
sellerId 是“谁发布”
product_id 是“问的是哪个商品”
```

**具体步骤**

1. `ChatRequest` 增加用户上下文字段，让请求可以携带当前用户的基础信息。
2. 在`main.py`转发 `user_context`，FastAPI 接收到用户上下文后，继续传给 Skybot 主逻辑。
3. 在`skybot.chat()`中增加参数，让 Agent 在处理用户问题时，能拿到当前用户信息，从而可以推荐更符合当前用户的商品。
4. 新增用户上下文格式化方法，把 JSON 用户信息转换成适合放进 Prompt 的文本。
5. 在商品推荐Prompt里面加入上下文，让 LLM 回答时可以参考当前用户的信息。

**总结**

> **Day11 主要完成了用户上下文接入。之前 Skybot 只能根据用户问题和商品数据进行回答，而现在请求中可以携带 user_context，让 Agent 在处理问题时知道当前提问用户的基础信息。这里的 user_id 表示正在使用 Skybot 的用户，而不是商品发布者；商品发布者对应的是商品数据中的 sellerId。本阶段的核心意义是为后续个性化推荐、对话记忆、权限控制和用户画像打基础。目前用户上下文只是简单注入 Prompt，后续可以继续接入用户学校、收藏记录、浏览记录、预算偏好等信息，让 Skybot 的回答更加个性化。**
