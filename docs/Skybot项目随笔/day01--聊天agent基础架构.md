## 核心想法

- 在确定好项目基本构架之后，开始搭建智能体最小的部分，也就是直接在终端提出问题，智能体将问题返回给大模型，大模型得出的答案在返回给Agent，Agent再将答案返回给用户。

**1.基础配置层**----负责管理项目运行参数

- 想要实现上面的基础最小循环，(在完成python基础环境配置后)我们需要在`.env`中设置全局可访问的基本文件，完成基本文件后我们需要额外添加配置文件，这里是为全局使用LLM打下基础，如果没有这一部分内容，可能调用大模型会非常麻烦，这里就相当于将麻烦的部分统一封装起来，既可以直接调用，也能方便后期修改。

**2.LLM模型层**----负责创建和封装大模型能力

- 在这个模型层部分，需要先与配置层区分：`config.py` 的职责是统一管理模型配置；`llm.py` 的职责是基于这些配置创建和封装大模型调用能力。前者负责“存参数”，后者负责“用参数”，两者共同实现配置与业务逻辑的解耦。
- 在模型层封装LL调用，先创建一个OpenAI客户端，这里的客户端就相当于用户，里面输入的大模型是`.env`内部的KEY和URL，然后在下面定义最小agent能力体现----实现基础的聊天；这个agent就相当于一个传话筒。
- 但是由于传话内容有准确的类型和规范，不符合类型和规范的内容就要被拦截并抛出异常，由于python代码的自动能力，这里直接使用`pydantic`来对请求体和返回体进行自动的检查，在代码中使用 ChatRequest 和 ChatResponse 来定义他们。
- ChatRequest 和 ChatResponse 本质上是接口的数据模型（Data Model），用于规定请求和响应的数据结构。它们既承担数据验证和过滤的职责，又充当客户端与服务端之间的数据合同，确保数据格式统一、安全、可控。

- 基本流程：

```
 客户端
   ↓
ChatRequest
   ↓
业务逻辑（Agent）
   ↓
ChatResponse
   ↓
客户端
```

**3.Agent智能体层**

- 我们的目的是实现最小聊天智能体，也就是说我们暂时跳过它的记忆与RAG系统，工具体系和一些其他的重要功能，目前我们已经拥有了大脑，现在来编写Agnet的主逻辑，首先需要创建一个简单的Agent对象，它目前只能调用LLM；我们在前面也规范了聊天的操作，现在就简单给这个Skybot加上chat功能，来进行测试。
- 这个智能体层其实就是写出一个智能体的类，并且在这个类中进行功能的扩展，现在我加入调用聊天功能(本质上就是将输出问题返回给大模型，再将答案返回给客户端)。

**4.API接口层**

- 基于FastAPI框架，我们可以更加简单的实现Agent的调用，在这个入口里将Skyron暴露成HTTP接口，方便以后直接通过HTTP请求调用。
- FastAPI 文件本质上是 Agent 的对外入口（API Layer），负责把 HTTP 请求转换为 Agent 调用，再把 Agent 的结果转换为 HTTP 响应返回给客户端。
- 在启动这个最小Agent项目后，可以直接在`http://127.0.0.1:8000/docs`上面测试新增的chat接口，实现与智能体的基本聊天。
