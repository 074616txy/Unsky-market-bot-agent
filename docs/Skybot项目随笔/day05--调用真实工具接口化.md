## 前言

- 目前，skybot暂时用的是给定的模拟数据和相应的工具函数完成的工具调用，真实场景下skybot的工具调用应该与Java后端项目的搜索功能联系，搜索的数据库也应该是Java后端的数据库，所以说今天的要求是：**把商品工具从“本地模拟数据”升级成“未来可以调用 Java 后端接口”的工具结构。**

**具体实现**

```
Skybot -> product_tool -> Java 商品接口 -> 真实商品数据
```

1. 在python中安装`requests`，它的作用是：**让 Python 主动去调用外部 HTTP 接口**。python通过`requests`可以实现对外部接口的调用。

2. 在 `.env` 加 Java 后端地址，方便让skybot和Unsky-Market实现联动。

3. 在 `config.py` 读取配置，将Java后端项目的本地网址配置到skybot文件中。

4. 扩展 `product_tool.py`，新增`search_product_from_api`，实现从接口完成工具的调用。

5. 添加一个统一工具入口，在这个入口可以进行切换 mock / api，实现对具体工具调用的管理。

6. 在Skybot 里改成调用统一入口，通过这个入口对工具进行合适的调用

> **以上操作只能说是为后续真实接口调用做好模板，里面代码的具体逻辑都还没有完善或者是已经写死的代码，后续联动Java后端后会进行完善补充。**

## 当前结果

- 已完成Agent真实工具调用的相关前置操作。
- 添加一个统一的调用工具函数，为后续多个工具调用提供统一入口。
- 为后续skybot和Unsky-Market项目的联动打下坚实的基础。
