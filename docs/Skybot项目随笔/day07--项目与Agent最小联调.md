**简单概述**

> 为了尽快开启下一章节，我就简单的叙述一遍我的想法；首先我对这一章节的认识就是实现Java后端项目与Agent项目两者的一个基础联调，虽然说现在的Agent项目方方面面还是有很大的缺陷(需要后期去完善)，这个联调就实现了简单的chat交流，其中的代码修改不是很多，我主要陈述一下具体逻辑以及操作缘由：

- 首先需要从整体上看待这两个项目，这两个项目本质上就是互不联系的两个整体，它们之间的关系不是简单的嵌套，而是两个服务端的调用。这也从根本上解释了Agent项目的完全独立性，在联调过程中不需要进行代码的修改；而在Java后端也不需要进行文件配置和maven环境依赖安装。
- 在联调中需要保证Java后端项目有Agent的模块，这也是要遵循整体Unsky-Market项目的后端工程架构，在这个软件包里面也要准备相应的小模块，比如说请求体和响应体封装要与Agent返回的一致、接口定义与实现类的代码功能实现以及在Java后端服务里创建一个Agent单独的chat接口；
- 这两个独立服务之间需要通过HTTP请求访问到，这个HTTP请求就像是这栋大楼之间的桥梁，保证这两栋楼之间的通行，而Java后端的dto里面规定了response和request就相当于门禁，用来规定这个桥允许那些人通行，这样就可以实现主服务Java后端对次服务skybot的调用
- 后续会继续在Java后端中添加相应可以解决实际问题的接口，当然这也需要伴随着Agent的成长，就相当于当Agent具备一项能力的时候，要想真正的在项目中使用它就需要在Java后端中暴露这个接口，通过调用这个接口来达到真正的调用。

> **Java 后端和 Skybot 是两个独立服务，它们之间通过 HTTP 请求进行通信。HTTP 请求可以理解为连接两栋服务大楼的桥梁，而 DTO 则规定了桥上数据通行的格式，保证 Java 发送的数据和 Skybot 接收的数据能够对齐，也保证 Skybot 返回的数据能被 Java 正确解析。**

> **后续当 Skybot 具备新的能力时，需要在 Java 后端中暴露对应的业务接口，让前端或其他模块可以通过 Java 主服务间接调用 Skybot。也就是说，Agent 能力本身在 Python 服务中成长，而这些能力真正进入 UnSky Market，需要通过 Java 后端接口完成业务接入。**
