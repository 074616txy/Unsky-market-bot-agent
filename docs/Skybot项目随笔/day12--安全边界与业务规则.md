## 前言

- 由于skybot是一个二手交易网站的小助手，它的发言必须具有安全约束并且符合业务规则，它不能做出一些欺骗、伪造数据等违背安全以及伤害用户的行为；所以我们就需要对它**增加统一安全约束 Prompt**，来让skybot具备安全意识并了解相关业务规则。

**具体操作**

1. 在 Skybot 类里新增方法`_build_safety_rules()`来约束skybot

```python
def _build_safety_rules(self) -> str:
    return """
安全与业务规则：
1. 只能基于平台接口返回的真实数据进行回答，不要编造商品、价格、卖家、交易结果。
2. 不能承诺商品绝对真实、交易绝对安全、卖家绝对可信。
3. 不能替用户完成下单、支付、退款、删除商品等真实业务操作。
4. 遇到数据不足时，要明确说明信息不足，而不是猜测。
5. 涉及交易风险时，要提醒用户通过平台正规流程沟通和交易。
6. 回答要以建议和辅助分析为主，不能代替用户做最终决策。
"""
```

2. 在Prompt里面引用这个`{safety_rules}`来增加安全边界与业务规则

```python
def _build_product_analysis_prompt(self, question: str, product_detail: str) -> str:
    safety_rules = self._build_safety_rules()
    
    return f"""
你是 Skybot，二手交易平台 UnSky Market 的智能商品分析助手。

{safety_rules}

用户的问题：
{question}

以下是商品详情数据：
{product_detail}

请你基于商品真实数据进行分析，不要编造不存在的信息。

请按照以下结构回答：
1. 商品基本情况
2. 价格是否合理
3. 成色和描述风险
4. 适合什么人购买
5. 最终购买建议
"""
```

3. 在商品搜索中加入这个安全边界的规则`{safety_rules}`

**总结**

> **Day12 主要完成了 Skybot 的安全边界和业务规则约束。由于 Skybot 是二手交易平台中的智能助手，它不能随意承诺商品绝对真实、交易绝对安全，也不能替用户完成下单、支付、退款、删除商品等真实业务操作。因此本阶段通过统一安全规则 Prompt 的方式，将业务边界注入到商品分析、商品推荐和普通问答等场景中。这样可以让 Agent 在回答时保持辅助建议的定位，基于平台真实数据进行分析，并在信息不足或存在交易风险时主动提醒用户谨慎判断。这个阶段的核心意义是让 Agent 不只是“能回答”，而是更符合真实项目中的安全要求和工程边界。**
